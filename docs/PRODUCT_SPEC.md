# 项目背景

企业内部存在大量的：

- 产品文档
- api文档
- 业务/运营规则
- 操作流程/规范
- 退款规则/流程

普通的RAG只能回答规则是什么、而运营人员可能问“帮我查询订单xxx为什么退款失败”

不仅要能查知识库，还要能查订单信息自动作出业务判断，这就需要AI Agent + business tool + workflow，既能查询业务知识，也能调用业务工具完成诊断

# 目标用户

V1只考虑两类

- 业务用户： 运营人员通过自然语言进行知识查询和业务诊断
- 管理员：上传业务文档维护知识库、维护知识库

# 核心用例

1. 运营人员问 “退款规则是什么”
2. 运营人员问 “订单xxx为什么会退款失败”
3. 管理员维护知识库
    - 上传pdf
    - 文档分片
    - 使用嵌入模型向量化
    - 建立索引
    - 知识存储
4. 管理员查看使用情况
    - 原始问题
    - 知识检索结果
    - 召回率
    - 召回的文档原文
    - 回答结果
    - token使用情况、耗时、错误等指标
    - 使用的模型

# V1功能范围

1. 用户登录、权限管理
2. 文档管理
3. LLM对话
4. 对话历史
5. Agent + workflow
6. business tool
7. rag召回
8. 异常追溯
9. token统计
10. 基础的评价

# V1明确不做

1. 复杂的多Agent
2. 复杂的RBAC
3. 大模型微调/优化
4. 分布式向量数据库
5. 移动端
6. 语音合成
7. 图像生成

只做基础功能

# 验收标准

用户可以登录然后根据用户角色展示不同功能，管理员可以上传pdf、进行向量化与索引创建和存储，还可以查看运营人员的使用记录，token用量和统计、文档召回率、运行异常等。运营人员可以询问业务规则以及进行业务诊断、可以查看自己的历史对话。

# 怎么算成功

两种用户角色都能流畅无障碍的使用，没有阻断性的bug，操作成功率99%。能通过dockercompose up -d 直接启动项目。项目长时间运行不会有内存泄漏等问题。
