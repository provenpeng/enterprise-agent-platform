# 知识库检索

`POST /api/v1/knowledge-bases/{id}/search` 使用已签名 JWT 中的 `tenant_id` 授权知识库，再为查询生成 Embedding。`admin` 和 `viewer` 都可检索；不存在或其他租户的知识库统一返回 404，不会调用模型。

请求示例：

```json
{"query":"退款需要谁批准？","top_k":5,"min_score":0.5}
```

`top_k` 范围为 1–20；`min_score` 范围为 0–1。先按精确余弦相似度取最多 `max(50, 5 × top_k)` 条授权候选，再在这个有界候选集内结合词项覆盖度重排，最后返回 `top_k` 条。词项使用中文相邻双字和拉丁字母数字词，按候选集内文档频率加权；章节路径可加权提示主题。排序结合原向量名次与词项覆盖度，余弦分数仍在每条 `hit.score` 中返回，因此最终列表的 `score` 不一定单调下降。`min_score` 始终先作用于余弦相似度，词项不能让低于阈值的分片进入候选。无命中时返回空数组。

每条命中包含分片 ID、文档 ID 与文件名、索引版本、分片序号、正文、页码、章节标题及章节路径，供后续问答接口生成和验证来源引用。分数为 `1 - cosine_distance`，截断至 0–1。诊断流程已知可信原因代码时仍使用严格代码过滤及精确余弦排序，不进行词项重排。

## 数据与隔离边界

查询只读取所请求租户和知识库的文档，且只读取 `Document.active_index_version` 指向、标识与当前 Embedding 空间一致的分片。标识由供应商 URL 或显式 `EMBEDDING_PROVIDER_ID`、模型名、原生维度和人工维护的修订号组成；不同向量空间不会混用。尚未发布、已被新版本替代、标识缺失或使用其他向量空间的分片不会出现。重建失败时活动版本仍保留；若此时已切换 Embedding 空间，需要恢复原配置才能检索旧版本。SQL 使用 PostgreSQL `MATERIALIZED` CTE 先筛出授权的活动分片，再做精确余弦距离排序，防止全局 ANN 候选集经过租户过滤后数量不足。大知识库仍需计算其全部活动向量的距离；词项重排也无法救回向量候选池之外的章节。将来若引入分区、租户内 ANN 或独立词项召回，需要用同一套租户、版本和 Recall@K 测试验证结果。

查询 Embedding 与索引使用相同的模型和原生维度配置，统一转为 1536 维存储向量。API 进程需要 `EMBEDDING_API_KEY` 或默认的 `OPENAI_API_KEY`；未配置、超时或模型返回无效向量时返回 503。API 使用独立的 `RETRIEVAL_EMBEDDING_TIMEOUT_SECONDS`（默认 15 秒），不影响 worker 的索引超时。服务端日志记录故障，响应不会泄露供应商异常或密钥。

`backend/tests/test_retrieval.py` 与 `test_answer.py` 用固定向量和真实 pgvector 数据库验证候选、阈值、Top-K、活动版本、未发布分片、跨租户授权、词项救回及供应商故障，不消耗模型额度。线上语义质量仍需有标注的真实查询集持续衡量；固定向量测试验证检索契约，不代表自然语言 Recall@K。
