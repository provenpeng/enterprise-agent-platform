# 租户隔离设计

## 信任与授权边界

API 只信任由配置的 RS256 公钥验证，且 `iss`、`aud`、`iat`、`exp` 均有效的 Token。Token 必须包含 UUID 格式的 `tenant_id` 和 `admin` 或 `viewer` 角色。生产环境由身份服务管理租户成员关系并签发这些声明。本地私钥只用于演示，不进入 API 镜像或挂载目录。

租户管理员可以创建当前 Token 指定的租户、维护知识库与文档；查看者只能读取。`owner_sub` 保留创建者审计信息，不用于跨成员读取授权。API 从 Token 获取租户 ID，所有知识库列表和按 ID 访问都加租户条件。文档、任务和分片通过知识库关系校验租户；跨租户资源统一返回 404。索引 worker 处理数据库中的任务，不接收用户指定的租户 ID。

## 数据库与迁移

`knowledge_bases.tenant_id` 为非空外键，知识库名称在租户内唯一。文档、任务、分片通过既有外键归属知识库。迁移为每个旧 `owner_sub` 建立独立租户，ID 为 `uuid5(NAMESPACE_URL, "enterprise-agent-platform:" + owner_sub)`。旧的 `legacy-unassigned` 主体对应租户被认证层拒绝，避免历史未归属数据被意外访问。管理员必须审查这些记录后再改写 `tenant_id`。

迁移脚本不会推断真实企业租户关系。需要将旧知识库合并到新租户时，应由管理员审核名称冲突和成员权限后执行显式数据迁移。应用查询保留租户条件，供后续检索与问答复用。
